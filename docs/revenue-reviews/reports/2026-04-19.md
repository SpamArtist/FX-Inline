## 5. Marketplace and review intelligence

### FX Inline's public sentiment problem

- Firefox Add-ons still shows `0` reviews.
- Extpose still shows `0` installs and `0` votes for the Chrome listing mirror.
- FX Inline does not have a public trust layer yet. No reviews plus version mismatch plus generic site copy is a bad combination.

### Positive themes across competitor reviews and marketplace copy

- Users love staying on the page instead of switching tabs.
- Hybrid models win: automatic conversion plus right-click or selection conversion.
- Privacy and local-storage claims help when the UX is already good.
- Merchant buyers care about visible outcomes:
  - local prices
  - location-aware pricing
  - fewer buyer questions
  - fast support when setup is messy

### Negative themes across competitor reviews

- Setup complexity gets punished fast.
- Wrong values destroy trust immediately.
- Performance complaints are brutal on dynamic pages.
- Highlight styles can hurt readability, especially on dark mode.
- Broken save behavior and weak defaults make the extension feel unreliable.
- Mobile incompatibility gets punished hard in the Shopify ecosystem.

### Recurring feature requests

- more currencies and symbols
- better frequent-currency defaults
- highlight or display-style controls
- tax or fee adjustments
- mobile support
- allowlist or blocklist behavior
- clearer support for dark mode readability

### Trust concerns

- API-key exposure was explicitly called out in competitor reviews.
- Data collection declarations matter, even for tiny extensions.
- Zero reviews create a cold-start credibility problem that no amount of feature boasting fixes.
- In Reddit launch threads, builders repeatedly sell "no tracking," "no accounts," and "open source" because users are already suspicious.

### Revenue-relevant review takeaways

- Simplicity is a growth feature.
- Accuracy is a trust feature.
- Performance is a rating feature.
- White-glove support is a selling feature for B2B localization buyers.
- FX Inline should not ship more consumer complexity before it ships more trust.

43. Ask for a testimonial or permission to show a before / after case study as part of the pilot agreement.

   one quote

### What can be parallelized with AI coding tools

48. Website rewrite, new HTML pages, analytics hooks, FAQ copy integration, and manifest polish can all happen in parallel once the wedge is chosen.
49. Prospect-list enrichment and personalized landing-page variants can also run in parallel.
50. Trust and support pages can be written while demo assets are being produced.

### What can be accelerated with AI design tools

51. Hero mockups, screenshot cleanup, annotations, comparison visuals, and listing graphics can all be produced far faster than hand-designing them.
52. Short demo loops and static thumbnails can be created the same day as the website rewrite.

### What remains serial even with AI

53. Choosing the wedge.
54. Getting real buyer responses.
55. Learning from objections.
56. Closing the first pilot.

### Metrics to monitor

57. Website CTA click-through rate.
58. Outbound reply rate.
59. Discovery calls booked.
60. Pilot close rate.
61. Time from outreach to first paid commitment.
62. If consumer work runs in parallel later:
   install count
   review count
   uninstall rate

### Risks

63. First risk:
   the chosen wedge does not care enough.
   Mitigation: test three wedges with the same core offer before expanding product scope.
64. Second risk:
   version drift and weak trust surfaces kill response.
   Mitigation: fix the public metadata story before serious outreach.
65. Third risk:
   dynamic-page performance or false positives break demo credibility.
   Mitigation: demo on pages the runtime already handles well, then extend only for real pilot targets.
66. Fourth risk:
   you build a snippet or productized package before the sales motion proves demand.
   Mitigation: pilot first, extraction later.

### Rollback considerations

67. If outbound does not produce traction after 30-40 targeted attempts across three wedges, stop adding product features.
68. Either reposition the offer or shift to package-led developer credibility with licensing and support.
69. Do not respond to weak demand by building subscription plumbing.

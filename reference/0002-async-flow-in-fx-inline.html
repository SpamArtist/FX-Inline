Quick Reference

Async Flow in FX Inline

Keep this open while reading the extension’s background, rates, and hydration code. It compresses the async patterns that recur in this repository.

1. async means “returns a Promise”

async function getRates() {
  const cached = await getCachedRateSnapshot();
  return cached;
}

The important reading rule is simple: every async function is delayed work, even if its body looks linear.

2. await marks a pause point

When you scan a file, box every await. Those are the places where the function can pause, fail, or depend on outside state.

3. Promise.all([...]) means parallel work

await Promise.all([
  scheduleRateRefreshAlarm(),
  getRates({ forceRefresh }),
]);

Read this as “start both operations now, then wait until both finish or one fails.”

4. try/catch defines fallback behavior

try {
  const fetched = await fetchLatestUsdSnapshotFromClient();
  return fetched;
} catch (error) {
  if (isValidSnapshot(cached)) return cached;
  throw error;
}

In this repo, catch often means “use cached data” or “return safe null state” instead of crashing.

5. Dynamic import(...) means lazy loading

const [{ getUserSettings }, { getCachedRateSnapshot }] =
  await Promise.all([
    import("../utils/appStorage"),
    import("../utils/rates/cache"),
  ]);

Read this as “load these modules only when needed, then unpack the exports.”

6. void somePromise.catch(...) means fire-and-observe

void initializeRateRefresh().catch((error) => {
  logRateRefreshError("onStartup", error);
});

The code is intentionally not awaiting the promise at that call site, but it still attaches error handling so rejections do not disappear.
